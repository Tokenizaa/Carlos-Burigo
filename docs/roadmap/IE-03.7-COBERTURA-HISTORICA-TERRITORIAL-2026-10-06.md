## 3. Arquitetura de ingestão — staging local

A partir de 2026-10-07, os dados eleitorais brutos e a consolidação pesada **não serão carregados diretamente no Supabase remoto**.

A cadeia canônica passa a ser:

`TSE → arquivos brutos locais → PostgreSQL local → validação/normalização/consolidação → publicação filtrada → Supabase remoto`

O PostgreSQL local é a fonte completa de ingestão e auditoria. O Supabase remoto é a fonte exclusiva de dados para o runtime da Inteligência Eleitoral.

### Local

O ambiente local mantém:

- arquivos ZIP/CSV/JSON oficiais do TSE;
- dados eleitorais consolidados;
- camadas intermediárias necessárias à validação;
- cruzamentos históricos e territoriais;
- cargas completas de RS/Deputado Estadual.

O banco local é executado pelo Supabase CLI sobre Docker.

### Remoto

O Supabase remoto permanece como **base operacional da Inteligência Eleitoral** e recebe somente os dados consolidados necessários à aplicação.

Não deve receber os arquivos brutos nem camadas intermediárias volumosas.

Essa separação evita consumir o armazenamento operacional do projeto remoto com staging eleitoral.
